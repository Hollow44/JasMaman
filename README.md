# Jas Maman — мониторинг молодых специалистов

Новая система вместо ИС «УМОСК» (учёт молодых специалистов и студенческих кредитов): учёт обучающихся по государственному
образовательному гранту, распределение, мониторинг отработки, взыскание бюджетных средств.
Построена на Yoda App (шаблон `yoda-web-sln-v2`, .NET 8), по образцу `keleshek`.

- Бизнес-процессы: `БП УМОСК.md` (исходный документ, структурированный)
- Данные legacy в fin_center: [docs/fin_center-umosk.md](docs/fin_center-umosk.md)
- Модель данных: [docs/domain-model.md](docs/domain-model.md)

## Решение

| Проект | Назначение |
|---|---|
| `JasMaman` | Веб-приложение (Startup, конфигурация, миграции БД `db/dbJasMaman`, UI-пакеты) |
| `JasMaman.Modules` | Модули предметной области (ниже) |
| `JasMaman.FcMigrator` | Чтение fin_center (PgOrm из keleshek.GonsMigrator): `schema.json`, оверрайды, сгенерированные модели |
| `JasMaman.FcProbe` | Консольная утилита разведки fin_center (`ping`, `umosk`, `dump`, `check`, `refs-check`, `sql`) |
| `JasMaman.Tests` | Модульные тесты правил, операций, маппинга legacy, импорта, уведомлений |

### Модули (`JasMaman.Modules/Modules`)

| Модуль | Что делает |
|---|---|
| `Grants` | Агрегат **Грант** (МС × уровень образования): обучение → выпуск → распределение → отработка → взыскание. 18 операций с журналом, реестры, карточка, справки, сводка, загрузка ответов о трудоустройстве, контроль отсрочек |
| `Catalogs` | Организации образования и специальности |
| `Notifications` | Уведомления МС: формирование, утверждение руководителем, отправка (шлюз), статусы доставки |
| `Migration` | Перенос из УМОСК: справочники, вузы/специальности, гранты; проверка сопоставления справочников; журнал |
| `References` | Справочники-enum с таблицами сопоставления legacy-значений |
| `Common` | Кабинеты (`Projects`), роли (`Roles`), ключи БД |

### Операции по гранту (`Grants/Ops`)

Каждая операция — класс `GrantOpDefinition<TModel>`: проверка доступности (роль + состояние), валидация,
чистая функция `Apply(state, model)` и форма. Запись состояния и журнала — общая (`Prepare` / `InvokeAsync`).

| Этап БП | Операции |
|---|---|
| 1. Ожидаемый выпуск (ВУЗ.1–3, 7) | Регистрация обучающегося, Изменение статуса студента, Изменение контактов, Обновление из ГБД ФЛ, Приказ об окончании |
| 2. Распределение (ВУЗ.4–5) | Распределение (основной / доп. протокол), Освобождение, Отсрочка, Завершение отсрочки |
| 3. Мониторинг | Период работы, Статус мониторинга, Закрытие отработки, Примечание |
| 3. Взыскание | Статус взыскания (ТКС), Расчёт суммы возмещения, Оплата, Прекращение обязательства |
| Миграция | Перенос из УМОСК (только системное задание) |

### Кабинеты и роли

| Кабинет (`projectsConfig`) | Поддомен | Кто работает |
|---|---|---|
| `JasMamanInternal` | `jas-maman-internal` | Департамент мониторинга, его руководство, ЮД, бухгалтерия |
| `JasMamanUniversity` | `jas-maman-university` | Организации образования — только свои студенты (по БИН) |
| `JasMamanModerator` | `jas-maman-moderator` | Модератор: миграция, справочники |
| `JasMamanPublic` | `jas-maman` | Публичная страница |

Роли (`db/dbJasMaman/seeds/All/R__Seed_Roles.sql`, константы — `Common/Roles.cs`):
Модератор, Департамент мониторинга, Руководитель департамента мониторинга, Юридический департамент, Бухгалтерия, Организация образования.
Права на операции проверяются в коде операций (`GrantOpUserContext`), а не через права модулей.

## Локальный запуск

1. PostgreSQL с pgsodium (как для keleshek), порт 5435:

   ```
   docker run --name PGSODIUM -p 5435:5432 -it -e POSTGRES_PASSWORD=123456 -v C:/pgsodium_getkey.sh:/usr/share/postgresql/16/extension/pgsodium_getkey.sh -d nexus.dc.servers.lan:8084/pg/pgsodium:latest -c 'shared_preload_libraries=pgsodium'
   ```

   где `C:/pgsodium_getkey.sh` создаёт ключ: `KEY_FILE=$PGDATA/pgsodium_root.key; [ -f "$KEY_FILE" ] || head -c 32 /dev/urandom | od -A n -t x1 | tr -d ' \n' > $KEY_FILE; cat $KEY_FILE`.

2. Создать БД `dbJasMaman` (`CREATE DATABASE "dbJasMaman"`). Миграции применяются автоматически при старте.
3. Добавить в `hosts` содержимое `JasMaman/!Development/hosts.txt`.
4. Строка подключения к fin_center (нужна только для миграции и FcProbe, требует VPN):

   ```
   dotnet user-secrets set "dbFcConnectionString" "Host=...;Port=...;Database=...;Username=...;Password=..." --project JasMaman.FcProbe
   ```

   (общий `UserSecretsId` = `secrets-of-jas-maman` у веб-проекта и утилиты).
5. Запуск: профиль `Yoda Development`, например `http://jas-maman-internal.test.me:23751/ru/grants/stats`.

Если внутренний NuGet (nexus) недоступен — `dotnet restore --ignore-failed-sources` (пакеты берутся из локального кэша).

## Изменения схемы БД

Таблицы описываются в `DataSchema()` модулей (`QueryTable`). Миграция генерируется сравнением с локальной БД:

```
powershell -File tools/gen-migration.ps1
```

Скрипт создаёт черновик `db/dbJasMaman/migrations/!V..._code-gen.sql`; после проверки уберите `!` из имени.
Пока черновик не принят, приложение не стартует (Yoda проверяет имена файлов миграций).

Ошибки сборки кратко: `powershell -File tools/build-errors.ps1`.

## Перенос данных из УМОСК

Кабинет модератора → «Миграция из УМОСК»:

1. **Проверка справочников** — каждое значение справочников fin_center должно иметь соответствие (`Migration/LegacyReferenceMap.cs`). То же из консоли: `dotnet run --project JasMaman.FcProbe -- refs-check`.
2. **Перенос вузов и специальностей** (ct317, ct316).
3. **Перенос молодых специалистов** — записи обучения по гранту (ct322) с персоной (ct320) и отработкой (ct520). Задание обрабатывает страницы по 500 записей, продолжает себя само и пишет ход в **Журнал миграции**; повторный запуск идемпотентен и не затирает данные, внесённые в Jas Maman.

Сопоставление записи УМОСК → грант: `Migration/LegacyGrantMapper.cs` (покрыто тестами).

## Интеграции

| Интеграция | Статус |
|---|---|
| ГБД ФЛ (ФИО, дата рождения, адрес прописки) | Операция «Обновление из ГБД ФЛ» через IntegrationHub |
| ГБД ЮЛ, БМГ | Не подключены (работодатель и телефон вводятся вручную, формат телефона проверяется) |
| КазПочта (гибридная почта), ПЭП, SMS | Интерфейс `INotificationGateway`; сейчас `LoggingNotificationGateway` (не отправляет). Реальная реализация регистрируется вместо неё в `NotificationsModule.ConfigureServices` |
| МТСЗН, МИО, Карьерные центры | Загрузка ответов из Excel: «Загрузка ответов о трудоустройстве» |
| ЕПВО, КГД | Не подключены (нет в текущем БП) |
| ЭЦП подписание уведомлений | Утверждение руководителем фиксируется в системе; подписание ЭЦП — к доработке вместе с подключением КазПочты |
