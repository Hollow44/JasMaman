# Данные УМОСК в fin_center

Карта таблиц legacy-системы УМОСК в базе `fin_center` (PostgreSQL 13.6), собранная утилитой `JasMaman.FcProbe`.
Бизнес-процессы — в `БП УМОСК.md`.

Как смотреть самому:

```
dotnet run --project JasMaman.FcProbe -- umosk          # таблицы УМОСК и число строк
dotnet run --project JasMaman.FcProbe -- dump ct360     # содержимое таблицы/справочника
dotnet run --project JasMaman.FcProbe -- columns ct520  # физические колонки
```

Физически таблицы — `ctNNN` с колонками `cmNNNN`; логические имена берутся из `JasMaman.FcMigrator/Schema/schema.json`.
Справочники (`::спр::`) в основном лежат в общей таблице `ct312` с фильтром по `c_class_id` — это описано в `JasMaman.FcMigrator/Overrides/*.json` (генерируются из БД при первом запуске).
Актуальные версии записей: `c_tr_id = 0`.

## Что это говорит о БП

1. **ТКС** — статус заёмщика по уровню образования. `ИП` и `Архив (по решению суда)` — **разные** статусы; есть ещё `Отработано`, `Умершие`, `по решению суда (отказ)`, `Инвалидность`.
2. **Отсрочка** в данных уже частично разделена: тип места «Отсрочка … магистратура (KZ)» и «… (зарубеж)» в ct583, статус «Временная отсрочка» в ct664, в ct520 есть `срок_отсрочки`, `дата_начало`/`дата_окончание`. То есть «Освобождён» не единственный способ записать отсрочку.
3. **Статусов три слоя**, которые в БП описаны одним словом «статус»: движение (ct314) → статус мониторинга (ct664/ct539) → ТКС (ct360). В новой системе их стоит явно разделить.
4. **Все признаки — по уровням образования** (бак/маг/рез/док) прямо в полях Персоны (`умсМ_`, `умсР_`, `умсД_`). В новой системе лучше отдельная сущность «обязательство по уровню».
